# `--algo keep_bf16`: structural BF16 exceptions (NEW)

`keep_bf16` keeps the layers an explicit structural rule selects in BF16. It is opt-in: no named
recipe includes it, and nothing is kept in BF16 unless the command line asks for it. Stack it onto
a recipe or an algorithm:

```
--algo atlas_v1_awq+keep_bf16:rule=input_conv
```

The whole rule and its parameters are NEW (no source defines them). It replaces the v1.0
`atlas_v1` behaviour that kept one module path of the Multi-Task DiT in BF16 when the policy type
string matched; that exception was keyed on a model name and a module path and silently stopped
applying if either changed.

## Rules

| Rule | Selects | Parameters |
|---|---|---|
| `input_conv` | every `nn.Conv2d` with `in_channels == channels` and `groups == 1` | `channels=N` (default 3, RGB) |

`input_conv` targets a convolution that reads the model's pixel input directly: the patch
embedding of a ViT / CLIP / SigLIP vision tower, or the stem of a CNN encoder. The structural
proxy is the input channel count of an image. It is derived from the module tree only (module type
and shape), never from a model name or module path.

Limits, stated so they can be checked:

- A deeper convolution that happens to have `channels` input channels would also be selected.
  The record lists every selected fqn (`members[].selected`), so such a selection is visible.
- A depthwise convolution (`groups > 1`) is not selected.
- A model without such a convolution selects nothing (TinyLlama: empty, outputs bit-identical
  to the same stack without `keep_bf16`).
- The SigLIP vision towers of SmolVLA and Pi0 embed patches with an RGB `Conv2d`, which the rule
  also selects when it is enabled there. On the Multi-Task DiT it selects the CLIP patch embedding
  (`observation_encoder.vision_encoder.model.vision_model.embeddings.patch_embedding`, checked by
  a slow test against the cached checkpoint).

## Application and records

The rule runs through the `bf16_exact(model, mode) -> {fqn: reason}` hook (`src/algos/base.py`).
`algos.quantize` resolves and validates the selected sites (each must be an `nn.Conv2d`) before
calibration, so they never reach calibration folds or cast hooks, and keeps them by exact fqn, so
similarly named siblings stay quantized. The result entry records:

- `algo.bf16_opt_out` and `algo.bf16_opt_out_exact`: the selected fqns;
- `algo.bf16_opt_out_reasons`: one reason per site, generated by the rule
  (`keep_bf16 rule=input_conv: Conv2d in_channels=3 == channels=3, ...`);
- the member record: `rule`, `channels`, `selected`.

An export writes each site with status `host`, the rule's reason and `match: exact`
([export.md](export.md)); `--from-export` replays the exact exclusion without calibration. On chip
profiles the convolution is host / VPU work: BF16 has no MXU operand path (pending ruling R4).

## Evidence

Run 5.2 measured the DiT patch embedding in BF16 on the SmoothQuant candidate at `ref_conv` only
(200 frames: 0.1394 -> 0.0883 rel L2 vs BF16; the incremental gain is within the separate
harness's 0.0559 floor). It has not been measured on the AWQ stack or on chip; run 6
(`5731fc0`) measures `atlas_v1_awq+keep_bf16:rule=input_conv` on the DiT at `ref_conv` and
`chip`.

## Tests

`tests/test_algo_keep_bf16.py`: selection on a synthetic RGB conv (not its 4-channel sibling or a
depthwise conv), `channels=1`, nothing on TinyLlama, refusal of a missing or unknown rule, off by
default in every recipe, exact application and recorded reasons, and the DiT patch embedding on
the cached checkpoint (slow). `tests/test_export.py` checks the export and reload records.
